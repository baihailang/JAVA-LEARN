## 2.Runable
### 1. 核心作用（是什么？）

`Runnable` 是一个**函数式接口**（`@FunctionalInterface`），里面只有一个抽象方法 `void run()`。

它的核心作用只有一句话：**定义“任务”本身，而不是“执行任务的线程”。**

- **逻辑与线程解耦**：`Runnable` 只负责封装“要执行的代码块”（业务逻辑），而不管这个代码块是由`new Thread`跑，还是丢给线程池跑，或者是用`ScheduledExecutorService`定时跑。
    
- **单继承的救星**：因为Java类是单继承，如果继承了`Thread`类就不能再继承其他类了。而实现`Runnable`接口，类还能继承其他父类，更加灵活。
    

---

### 2. 常用于什么？（3大场景）

- **场景一：创建并启动线程（基础写法）**  
    这是最经典的用法，把任务丢给`Thread`对象去执行。
    
    java
    
    // 传统匿名内部类
    new Thread(new Runnable() {
        @Override
        public void run() {
            System.out.println("任务执行中...");
        }
    }).start();
    // 现代写法（Lambda表达式，因为它是函数式接口）
    new Thread(() -> System.out.println("任务执行中...")).start();
    
- **场景二：配合线程池（最核心、最高频）**  
    在实际企业级开发中，**几乎不会直接用 `new Thread`**，而是使用线程池（`ExecutorService`）。线程池接收的任务绝大多数都是`Runnable`（或`Callable`）实现类。
    
    java
    
    ExecutorService pool = Executors.newFixedThreadPool(10);
    pool.execute(() -> {
        // 执行批量插入数据库、调用第三方接口等耗时操作
        doSomething();
    });
    
- **场景三：定时任务调度**  
    配合`ScheduledExecutorService` 做延迟或周期性的任务执行。
    
    java
    
    ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(5);
    scheduler.scheduleAtFixedRate(() -> {
        // 每隔1分钟清理一次临时缓存
        cleanCache();
    }, 0, 1, TimeUnit.MINUTES);
    

---

### 3. 灵魂对比：Runnable vs Callable（面试常问）

既然你正在学并发，必须分清这个，面试必考：

| 对比项        | **Runnable**                               | **Callable**                       |
| ---------- | ------------------------------------------ | ---------------------------------- |
| **核心方法**   | `void run()`                               | `V call()`                         |
| **是否有返回值** | **无**。不能返回结果。                              | **有**。支持泛型返回值（通过`Future.get()`获取）。 |
| **是否抛异常**  | **不能**抛出受检异常（checked exception），异常只能在内部处理。 | **可以**抛出受检异常（异常会封装在`Future`中）。     |
| **使用场景**   | 执行无需返回值、丢进去就不管的任务（如日志记录、数据同步）。             | 执行需要获取执行结果的任务（如异步计算、RPC调用获取数据）。    |

---

### 4. 一点小贴士（避坑）

- **Lambda简写**：因为`Runnable`是函数式接口，在代码中写`() -> {}`即可，不要再写`new Runnable()`这种啰嗦的匿名类了（除非你的JDK版本低于1.8）。
    
- **异常处理**：因为`run()`方法不允许`throws Exception`，所以对于受检异常（如`IOException`），你**必须**在`run()`方法内部用`try-catch`捕获，否则编译报错。这也是很多新手容易卡住的地方。
```java
package com.baihailang;

  
//实现Runable类
public class RunableImpl implements Runnable {

  

    @Override

    public void run() {

        Thread t2=Thread.currentThread();

        String t2Name=t2.getName();

        System.out.println("Hello, World! My name is " + t2Name);

    }

  

}



package com.baihailang;

  
//调用实现
public class Test2 {

  

    public static void main(String[] args) {

        new Thread(new RunableImpl()).start();

    }

  

}



```



## 3.Threadlocal
### 核心作用

一句话概括：**`ThreadLocal` 为每个线程提供独立的变量副本，实现线程间的数据隔离**。

它的核心价值体现在两方面：

1. **解决线程安全问题**：每个线程操作自己的副本，互不干扰，从根本上避免了多线程并发访问共享变量时的数据竞争[](https://baike.baidu.com/item/ThreadLocal#2#1)。它与 `synchronized` 不同，后者解决的是**多线程间共享数据**的同步问题，而 `ThreadLocal` 解决的是**多线程间数据隔离**的问题。
    
2. **简化参数传递**：在同一个线程的复杂调用链路中，可以将数据存入 `ThreadLocal`，后续任何地方都能方便地获取，无需在方法间层层传递参数[](https://developer.aliyun.com/article/1610514#1)。
    

### 常见使用场景

- **Web应用中的用户会话/上下文信息**：一个HTTP请求通常由一个线程处理，可将当前登录用户的信息存入`ThreadLocal`。这样在请求处理的任何环节（如Service、DAO层）都能随时获取用户信息，无需在方法参数中反复传递[](https://bbs.huaweicloud.com/blogs/460218#1)。
    
- **数据库连接与事务管理**：确保同一线程内的多个数据库操作使用的是同一个`Connection`对象，从而保证事务的一致性。Spring框架的`TransactionSynchronizationManager`就是利用`ThreadLocal`来管理事务资源的典型例子[](https://developer.aliyun.com/article/1657593#1)。
    
- **线程不安全的工具类**：如`SimpleDateFormat`和`Random`，在多线程下共享容易出问题。通过`ThreadLocal`为每个线程创建独立实例，既能保证线程安全，又能复用对象，避免频繁创建的性能开销[](https://developer.cloud.tencent.cn/article/2560499?policyId=1004)。
    
- **全链路追踪ID (TraceId)**：在微服务或复杂系统中，为每个请求生成唯一的`TraceId`并存入`ThreadLocal`，便于在日志中串联一次请求的完整调用链，实现分布式追踪[](https://developer.aliyun.com/article/1610514#1)[](https://developer.aliyun.com/article/1657593#1)。
    

### ⚠️ 使用注意事项

使用`ThreadLocal`时有一个关键风险：**内存泄漏**。

`ThreadLocalMap`中的`key`（即`ThreadLocal`实例本身）是**弱引用**，但`value`是**强引用**[](https://developer.aliyun.com/article/1657593#1)。当外部强引用被置为`null`后，`key`会被回收，但`value`因强引用而无法回收，若线程一直存活（如**线程池中的线程**），就会导致内存泄漏[](https://developer.aliyun.com/article/1657593#1)。

**因此，最佳实践是：在 `finally` 代码块中调用 `remove()` 方法清**
``` java
 package com.baihailang;

  
  
//Threadlocal
public class Test {

  

    public static void main(String[] args) {

       String name ="张三";

       int age = 18;

       String sex = "男";

       ThreadLocal<People> t1=null;

       try {

            t1 = new ThreadLocal<People>() {

            @Override

            protected People initialValue() {

                return new People(name, age, sex);

            }

            };

            String nameget =t1.get().getName();

            System.out.println("Hello, World! My name is " + nameget);

       } catch (Exception e) {

            e.printStackTrace();

       }finally {

            if (t1 != null) {

                t1.remove();

            }

        }  

    }

}

```


##  4.callable
### Callable 的作用与常见使用场景

#### 1. 核心作用（是什么？）

`Callable` 是一个位于 `java.util.concurrent` 包下的**函数式接口**（`@FunctionalInterface`），里面只定义了一个方法：

java

V call() throws Exception;

它的核心作用在于：**定义一个具有返回值且能抛出受检异常的异步任务**。

相较于传统的 `Runnable`，`Callable` 填补了“异步执行后需要拿到结果”的空缺。它通常不直接交给 `Thread` 构造器，而是配合 **线程池（`ExecutorService`）** 和 **`Future`** 一起使用，用于提交任务并在未来某个时间点获取执行结果。

---

#### 2. 核心区别：Callable vs Runnable（面试高频）

|对比维度|**Runnable**|**Callable**|
|---|---|---|
|**核心方法**|`void run()`|`V call()`|
|**返回值**|**无**|**有**（支持泛型，通过 `Future.get()` 获取）|
|**异常抛出**|**不能**抛出受检异常（checked exception），异常只能在内部 `try-catch` 处理|**可以**抛出受检异常（异常会封装在 `Future` 中，调用 `get()` 时抛出）|
|**使用方式**|可传给 `Thread` 或线程池|**只能**通过线程池提交（`submit()` / `invokeAll()`），不能直接传给 `Thread`|
|**适用场景**|执行“丢进去就不用管”的无返回值任务（如日志记录、缓存更新）|执行需要获取执行结果或需要处理异常的后台计算任务|

---

#### 3. 常用于什么？（3 大场景）

##### 场景一：异步计算 / 批量数据查询（获取结果）

在需要执行耗时计算（如调用外部 API、复杂 SQL 统计），且主线程需要依赖其结果时使用。
```java
ExecutorService pool = Executors.newFixedThreadPool(5);
// 提交异步计算任务
Future<Integer> future = pool.submit(() -> {
    // 模拟调用远程接口计算金额
    Thread.sleep(3000);
    return 10086;
});
// 主线程可以在此做其他事情...
System.out.println("主线程继续干别的活...");
// 最后阻塞获取计算结果（如果任务未完成，get() 会阻塞）
Integer result = future.get();
System.out.println("异步计算结果：" + result);
```
##### 场景二：并行处理批量任务（提高吞吐量）

同时发起多个独立任务（如查询多个分片数据、调用多个微服务），统一等待所有结果返回，大幅缩短整体响应时间。
```java
ExecutorService pool = Executors.newFixedThreadPool(10);
List<Callable<String>> tasks = new ArrayList<>();
// 模拟查询 3 个不同系统的用户信息
tasks.add(() -> queryUserInfoFromSystemA("uid"));
tasks.add(() -> queryUserInfoFromSystemB("uid"));
tasks.add(() -> queryUserInfoFromSystemC("uid"));
// 并行执行，统一获取所有结果（超时机制兜底）
List<Future<String>> futures = pool.invokeAll(tasks, 5, TimeUnit.SECONDS);
for (Future<String> f : futures) {
    if (f.isDone() && !f.isCancelled()) {
        System.out.println("结果：" + f.get());
    }
}
```


##### 场景三：处理超时机制 / 服务降级

`Future.get(timeout, TimeUnit)` 可以设置最大等待时间，防止某些慢任务拖垮整体流程，配合异常捕获实现降级逻辑（返回默认值或兜底数据）。
```java
Future<String> future = pool.submit(() -> {
    // 可能非常慢的第三方接口
    return callSlowApi();
});
try {
    String data = future.get(2, TimeUnit.SECONDS);
    return data;
} catch (TimeoutException e) {
    // 超时后执行降级逻辑，返回本地缓存或默认值
    return "默认数据（降级）";
}
```


---

#### 4. 重要注意事项（避坑指南）

1. **`Future.get()` 是阻塞的**：调用 `get()` 方法时，若任务尚未完成，**当前线程会阻塞等待**。切记不要在主线程中过早调用 `get()`，否则会失去异步并行优势。建议在任务全部提交后再统一调用 `get()`。
    
2. **异常处理的时机**：`call()` 方法内部抛出的受检异常，会被封装为 `ExecutionException`，在调用 `future.get()` 时抛出，务必捕获处理（不要只捕获 `InterruptedException`）。
    
3. **线程池必须通过 `submit()` 提交**：`Callable` **不能**直接传入 `new Thread()` 构造器（因为 `Thread` 只接受 `Runnable`），必须配合线程池的 `submit()` 或 `invokeAll()` 方法。
    
4. **留意 `Future` 的取消**：如果任务不再需要结果，可以通过 `future.cancel(true)` 尝试中断任务，避免浪费系统资源。
